# WHU TOP Developer 能力裁定细则与执行流程

> 能力等级是与任务角色（助教 / 实习 / 科研）、积分排行完全解耦的一条统一评判标准。  
> 学生账号公开场合使用昵称；老师 / 发布方账号使用实名。

---

## 1. 总原则

1. **一条标准**：不按 INTERN / TA / RA 分套评级；任务类型只说明「你在做什么」，不改变「你被定成哪一档」。
2. **裁定 ≠ 积分**：积分只用于活跃激励与排行榜；**任何积分入账都不改变能力等级**。
3. **双路径评级**：**LV1–LV3** 由系统根据平台内**已完成工作**自动评定；**LV4 / LV5** 须主动提交「晋级裁定」申请，由平台 **管理员（ADMIN）** 或已认证的 **LV4 / LV5** 评定人终裁。
4. **仁慈独裁**（适用于申请终裁）：一人拍板，可参考申请材料与他人意见；宁缺毋滥，尤其是 LV4、LV5。
5. **评价范围**：以能否稳定完成校园协作项目中的日常开发与交付为准；用不到的能力不纳入评价。

---

## 2. 档位与标注

### 2.1 主档

| 等级 | 简称 | 定位 |
|------|------|------|
| LV0 | 无能力者 | 未建立基本编程回路 |
| LV1 | 低能力者 | 指导下可做函数级任务 |
| LV2 | 异能力者 | **招募 / 参与项目的基准线** |
| LV3 | 强能力者 | 可独立查错与独立切片交付 |
| LV4 | 大能力者 | 模块级独立 + 可带低等级伙伴；**可任裁定人** |
| LV5 | 超能力者 | 可领导小组并对交付负责；**可任裁定人** |

新注册学生默认：**LV0**（无见习、无 M）。

### 2.2 附加标注

| 标注 | 展示示例 | 含义 |
|------|----------|------|
| 见习 | `LV3见习` | 已超过上一档常态，但尚未稳定满足本档全部硬条件；处于培养阶段 |
| M | `LV4·M` | 以组织管理能力作为本档主要评价维度；技术可低于同档纯技术要求 |

两标注可并存，例如：`LV3见习·M`。

**见习说明**

- 例如【LV3见习】：超过了 LV2，但尚未完全满足 LV3 要求。
- 见习不是荣誉称号，表示「培养中」；再次申请时应优先证明缺口已补齐。

**M 说明**

- 带【M】的成员以其组织管理能力作为该档最高评价标准。
- 技术软底线：建议不低于目标档减 2（例如 LV4·M 的技术表现不低于约 LV2 稳定水平），否则应先补技术或降低 M 诉求。

## 3. 评价范围：什么算、什么不算

### 3.1 计入

完成真实软件协作所需的能力，例如：

- 编程与阅读代码
- 工程协作（git / PR、自测、构建与报错处理）
- **调试、分析查错**
- 沟通与文字记录（状态可追踪）
- 独立交付、拆任务与带人（中高档）

### 3.2 不计入

- 与日常协作无关的纯竞赛刷题、炫技
- 无法在协作中核验的口头经历
- 与平台协作无关的证书堆砌

申请材料可用于佐证，**最终以可核验的行为与交付为准**。

## 4. 各档硬性标准（统一）

### LV0 无能力者

- 没有用编程语言写过可运行代码，或尚未建立「编写 → 运行 → 修改再运行」的基本回路。
- 对基本数据结构与协作工具无概念。

**裁定要点**：确认为起点档。若申请人申请更高档，须用作品 / 仓库 / 演示加以核验；不能核验则不得抬高。

> 业务上一般不主动招募 LV0；若破格协作，属项目侧约定，不改变本细则条文。

---

### LV1 低能力者

须**同时**满足：

1. 至少一门编程语言达到：理解函数调用、能把源码跑起来、能完成简单的读写 / 处理 / 输出类小程序（语言不限：C/C++/Java/Python/JS/TS 等均可）。
2. 能在指导下阅读局部代码，完成函数级改动或小脚本。
3. 会基本 git：`clone` / `commit` / `push` / 简单 `branch`；理解 PR/MR 的用途。
4. 能按约定沟通（私信 / 周报等）：任务状态可追踪，不无故失联。
5. 会用常见命令行完成查看文件、搜索、进出目录等（不要求精通运维）。

**未满足任一条 → 不得定为 LV1**（可维持 LV0；仅当已接近时方可考虑 `LV1见习`）。

---

### LV2 异能力者（基准线）

在 LV1 基础上，须**同时**满足：

1. 对数据结构、算法基础、计算机组成 / 体系结构、数据库等有常识级了解，能够快速复习后上手（不要求竞赛级）。
2. **熟练使用 git，并具备良好的小组协作技能**（强调技能而非资历年限）：分支策略意识、PR 描述清楚、能响应 review。
3. 能在 mentor 指导下，大约一周量级内完成可合并的小功能或明确子任务，并完成自测。
4. 能调试**自己的**代码（断点 / 日志 / 复现步骤清楚）；能看懂构建与报错，并提问问到点子上。
5. 周报或等效记录能写清：做了什么、卡点、下一步。

**LV2 是默认可正常参与项目协作的基准。** 多数成员从此档起评或升到此档。

---

### LV3 强能力者

在 LV2 基础上，须**同时**满足：

1. **硬门槛：能够独立分析遇到的 bug / crash / 异常**——复现 → 定位 → 验证。这是 LV3 的准入条件。（不是只会把报错贴给别人。）
2. 能够独立承担约一周以上长度的开发切片；mentor 只需少量关键决策，而非手把手。
3. 一门语言熟练，另有一门脚本 / 胶水语言够用；能阅读英文技术资料完成任务。
4. 能够进行清楚的技术同步（口头或书面），结论可执行。

**独立查错未过关 → 最高给到 `LV3见习` 或维持 LV2，不得直接定为 LV3。**

---

### LV4 大能力者

在 LV3 基础上，须**同时**满足：

1. 能够独立承担**模块级**开发类工作，能快速学习新领域的最小知识集并推进。
2. 对较大、较陌生的代码系统，能独立完成调试与根因分析，并推动任务按时推进。
3. 能够指导 LV3 及以下伙伴：拆任务、卡点救援、质量把关。
4. 能够察觉并指出他人（含同级及以上）的错误或知识盲区，并推动纠正。
5. 能够根据需要，从 0 到 1 为团队撑起一个小方向（调研、分享、落地、可交接），而不是只做执行票。

**达到 LV4 的成员可作为能力裁定人。**

---

### LV5 超能力者

在 LV4 基础上，须**同时**满足：

1. 有能力独立分析和分解复杂问题，整合多方资源完成任务。
2. 能够指导 LV4 及以下，能够领导开发小组并保证交付。
3. 有能力应对突发情况，并代表团队与 mentor / 发布方沟通对齐。
4. 在授权范围内可根据现场状况调整策略与优先级，对结果负责。

**LV5 无论实习生或其它身份，都应具备领导一个开发小组的能力。人数应极少，宁缺毋滥。**  
**LV5 可作为能力裁定人。**

---

## 5. 申请材料（证据）

本节材料主要用于 **LV4 / LV5 晋级申请**；LV1–LV3 以平台内已完成工作为准，一般不要求另行提交申请单。

申请人应提供可核验材料，鼓励组合提交：

| 类型 | 示例 |
|------|------|
| 平台内 | 已参与项目、周报、结项材料、协作沟通记录 |
| 站外 | 代码仓库 / PR 链接、技术笔记、演示视频、过往证明（可选） |
| 自评（必填） | 目标档位、是否见习 / M、对照本细则的逐条说明（建议不少于 100 字） |

评定人可要求补材料，或通过私信约定简短确认。当面 / 视频确认非系统强制模块。

## 6. 评级路径：自动评级与申请裁定

### 6.1 总览

| 档位 | 路径 | 说明 |
|------|------|------|
| LV0 | 默认起点 | 新注册学生默认 LV0 |
| LV1–LV3 | **系统自动评级** | 依据平台内**已完成工作**对照第 4 节硬性标准评定 |
| LV4–LV5 | **主动申请 + 人工终裁** | 须提交晋级申请；由 ADMIN 或 LV4 / LV5 裁定人拍板 |

> **积分不参与自动评级**：活跃积分只进排行榜，**不会**因为积分高低自动抬升或压低能力等级。

### 6.2 LV1–LV3：按已完成工作自动评级

系统在可核验的协作事实之上，对照第 4 节各档「须同时满足」条款，对学生当前档位进行维持、抬升或给出见习态。

**主要依据（平台内）**

- 已入项项目的角色与持续参与情况
- 周报 / 进度记录的完整性与可追踪性
- 结项或阶段性交付、可合并的贡献记录
- 协作沟通中可核验的调试、自测、交付行为

**自动评级规则要点**

1. **只升不跳档（默认）**：一次自动评定通常最多抬升一档（如 LV1 → LV2）；跨档需连续多次满足更高档证据，或由 ADMIN 复核。
2. **硬条件全满足才定档**：例如未过「独立查错」门槛，不得自动定为 LV3，最多维持 LV2 或给出 `LV3见习`。
3. **见习可由系统给出**：已超过上一档常态、但本档硬条件未齐时，可自动标注见习（如 `LV3见习`）。
4. **自动降级审慎**：仅当后续协作长期明显不符已定档，或由 ADMIN 复核确认后，方可降级 / 取消见习；须写入流水并通知学生。
5. **M 标注不走自动路径**：`·M` 仅能通过申请裁定获得或取消。

**学生对自动结果有异议**：可向 ADMIN 申诉并补充说明；申诉处理属人工复核，不视为 LV4 / LV5 晋级申请。

### 6.3 LV4–LV5：申请裁定

1. **必须申请**：达到或自认接近 LV4 / LV5 时，须提交「晋级裁定」申请；系统**不会**因自动规则直接定为 LV4 / LV5。
2. **材料**：见第 5 节；须对照第 4 节 LV4 / LV5 硬性标准逐条说明。
3. **终裁人**：ADMIN，或已认证的 LV4 / LV5 裁定人（不得裁自己）。
4. **宁缺毋滥**：证据不足应驳回或改判为不高于 LV3（含见习）；尤其 LV5 应极少。
5. **见习 / M**：申请 LV4 / LV5 时可同时申请见习或 M；是否给予由终裁人决定。

### 6.4 升降级、冷却与回避

**可升可降**

- 自动路径：按 6.2 规则维持 / 抬升 / 见习；降级须审慎并留痕。
- 申请路径：证据充分可晋级、去掉见习、增加 / 去掉 M；证据不足可驳回或改判。
- 后续协作明显不符已定等级时，**ADMIN** 或 **LV4 / LV5 裁定人** 可降级、取消见习或 M（必须写明理由并记入流水）。

**冷却（仅申请路径）**

- 同一学生对**同一目标档位组合**（等级 + 是否见习 + 是否 M）被驳回后，**14 天内**不得重复提交相同目标。
- 材料有重大更新时，可申请由 ADMIN 解除冷却。

**利益冲突（仅申请路径）**

- 不得评定自己。
- 与申请人存在明显利益冲突时，应回避，改由其他裁定人或 ADMIN 处理。
