# 需求文档

## 1. 背景与目标

WHU TOP Developer（武大开发者社区，域名 whudev.org）面向全国高校学生。产品形态参考开源之夏 OSPP（<https://summer.ospp.ac.cn/>）的「组织发项目 → 学生申请书 → 导师指导 → 结项验收」，并结合 PLCT 周报管理与 Boss 直聘式沟通：whu.edu 发布方发 TA / Intern / RA，edu 学生投递协作入项并持续交付。强调自运转：PRD → 技术文档 → 节点推进（状态机、催办、超时升级）。

| 维度 | 说明 |
| --- | --- |
| 产品目标 | 可招人、投递、沟通、入项、周报评分、基础节点推进 |
| 成功标准 | 招满 ≥5 人；推进 1–2 个项目；既有 TA 与开发任务可持续招生 |
| 部署 | whudev.org |
| 公开参考 | 开源之夏 OSPP summer.ospp.ac.cn |

**范围原则。** 第一版只做最基本可上线且能自转的功能。补助仅任务页展示标准，MVP 不做支付；年经费量级（约 1000–4000/人月、年费约 40 万内）仅作运营心智，不进系统。不照搬 OSPP 的组委会劳务协议与统一暑期档期。

## 1.1 参考 OSPP：借鉴与差异

OSPP 关键链路：组织发布项目并指定导师 → 学生沟通并提交申请书 → 导师审核（建议一周内）→ 中选后开发 → 提交结项报告与 PR/MR → 导师与组委会结项审核。项目详情强调名称、背景与目标、难度、技术栈、产出要求、技术要求、仓库、开发周期、预估工时、学习资料；申请书质量是中选主标准；开发期建议每周沟通 1–2 次。

| 可借鉴 | 落到我们一期 |
| --- | --- |
| 结构化项目详情字段 | 任务/PRD 模板强制：类型、难度、技术栈、产出、周期、工时、仓库、资料、补助展示 |
| 申请书为主材料 | 投递需提交申请书（方案/计划），模板站内提供；质量作为筛选主依据 |
| 沟通后再申请 | 任务页可私信发布方；鼓励先沟通再投递 |
| 导师一周内审申请 | 投递超时未处理催办（默认 7 天） |
| 无人中选则持续开放 | 任务可长期开放直至招满或关闭 |
| 结项报告 + PR/MR 链接 | 结项节点必填结项报告与交付物/PR 链接 |
| 每周沟通 | 映射为周报 + 催办；老师评分代替中期大评审 |
| 难度档与报酬档 | 任务难度标签 + 补助标准文案展示（不做 OSPP 固定金额） |
| 领航：方向→提案→立项 | 二期可选：实验室发开放方向，学生提案后再生成正式任务 |

**不要照搬。** OSPP 是暑期开源活动 + 组委会双审 + 劳务协议与证书；我们是常年运行的武大开发者社区招聘与项目管理（TA/Intern/RA），发布方为 whu.edu，学生昵称老师实名，自运转节点与 L1–L5 成长体系是自有能力。一期不做组委会式二审、不做在线签约发薪。

## 2. 角色

| 角色 | 身份 | 要点 |
| --- | --- | --- |
| 学生 | 全国 edu 邮箱 | 昵称；申请书投递、私信、面试、入项、周报 |

| 管理员 | 内部账号 | 审核、人工等级、催办超时、配置 |
| 协调员 | 二期+ | 拆卡协助、跟进节点、催办升级 |

## 4.1 第一期 MVP

目标：最小闭环上线，支撑招满 ≥5 人、推进 1–2 个项目。系统管状态与催办，人做判断性确认。任务与申请形态对齐 OSPP，过程管理用周报与节点自运转。

| 能力 | 说明 |
| --- | --- |
| 注册认证 | 学生 edu；发布方 whu.edu；管理员；昵称/实名 |
| 结构化发任务 / PRD | 必填：类型（TA/Intern/RA）、名称、背景与目标、难度、技术栈、产出要求、技术要求、周期、预估工时、仓库链接、学习资料、补助标准展示 |
| 申请书投递 · 私信 · 面试 | 站内申请书模板；可先私信再投递；投递 7 天未处理催办；任务可持续开放；面试字段可选 |
| 入项 · 周报 · 评分 | 录用入项；每周周报；老师评分（对标每周沟通，不做统一中期大考） |
| 节点与结项 | 项目节点：需求确认 → 设计评审 → 开发交付；每周周报过程同步；结项验收单独提交报告与 PR；催办与超时升级 |
| 人工 L1–L5 + 管理后台 | 等级调整、超时队列、简单配置 |

**一期不做：** 在线支付与劳务协议签约、组委会式二审、积分自动升降级、自动建仓拆卡、协调员完整体系、GitHub 深度对接、完善排行榜与赞助展示、领航式开放方向（放二期）。

一期验收：

- [ ] edu / whu.edu 注册验证与昵称/实名正确
- [ ] 任务模板含 OSPP 风格必填字段；可展示补助标准
- [ ] 可提交申请书投递、私信、可选面试；7 天未审催办
- [ ] 可入项；周报与老师评分可用
- [ ] 需求确认 → 设计评审 → 开发交付 → 结项报告/PR 链接可跑通
- [ ] 人工 L1–L5 可维护；whudev.org 可访问

## 4.2 第二期：协作增强与激励

积分规则与流水、自动评级辅助、排行榜初版、补助台账、催办可配置、协调员雏形；可选「开放方向 → 学生提案 → 生成正式任务」（借鉴 OSPP 领航模式，简化版）。

- [ ] 积分规则与可查流水；等级可自动建议
- [ ] 排行榜维度与积分一致
- [ ] 补助台账可录入、按人/任务查询
- [ ] 协调员可处理指派范围内催办与节点
- [ ] 可选：开放方向与提案流程

## 4.3 第三期：建仓拆卡与 GitHub

自动建仓/绑仓、成员邀请；半自动拆卡；Issue/PR 状态回写（对齐 OSPP「以 PR/MR 合入为结项依据」的工程侧自动化）。

## 4.4 第四期：运营与品牌

多维排行榜、赞助展示、运营看板、通知与移动端体验。不做大而全社交信息流。

| 优先级 | 期次 | 关键词 |
| --- | --- | --- |
| P0 | 一期 | OSPP 风格任务与申请书、投递私信、入项周报、节点结项、人工等级 |
| P1 | 二期 | 积分评级、排行榜、台账、协调员、可选提案方向 |
| P2 | 三期 | 建仓拆卡、GitHub/PR 回写 |
| P3 | 四期 | 排行完善、赞助、运营看板 |

## 5. 非功能与待决

| 项 | 要求 |
| --- | --- |
| 安全 | HTTPS、密码哈希、角色鉴权、防越权、登录保护 |
| 邮件 | 验证与催办；SMTP + SPF/DKIM |
| 备案 | whudev.org 国内托管需预留 ICP 备案窗口 |
| 审计 | 等级、入项、关键状态变更留操作日志 |

实施前确认：申请书模板字段终稿；面试是否强制；节点超时默认阈值；技术文档一期载体（Markdown / 附件 / 外链）；积分细则放二期。

# 建设文档

## 1. 建设原则

| 原则 | 说明 |
| --- | --- |
| 先闭环，后自动化 | 一期人能用、事能转 |
| 身份可信优先 | edu / whu.edu 邮件验证先打通 |
| OSPP 形态 + 自运转骨架 | 结构化任务与申请书；节点状态机与周报催办 |
| 补助展示与台账分离 | MVP 无支付；台账放二期 |
| 够用技术栈 | 熟悉、易部署、易维护 |

## 2. 推荐技术栈

| 层级 | 推荐 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 或 React + TypeScript | 学生端 / 发布端 / 管理端分路由 |
| 后端 | NestJS/Express 或 Django/FastAPI | 权限与状态机在服务端 |
| 数据库 | PostgreSQL | 用户、任务、申请书、消息、节点、周报、评分 |
| 队列（可选） | Redis | 会话、限流、异步邮件 |
| 文件 | 本地或 S3 兼容 | PRD / 申请书 / 结项报告附件 |
| 入口 | Nginx + Docker Compose | TLS、反代；应用+DB |
| 三期 | GitHub App / OAuth | 建仓、邀请、PR/Issue 同步 |

一期不引入：支付网关、劳务协议电子签、商业工作流引擎、多租户中台。

## 3. 信息架构

| 区域 | 内容 |
| --- | --- |
| 公开 | 首页、任务列表/详情（OSPP 风格字段）、登录注册 |
| 学生端 | 申请书投递、私信、项目/入项、节点与文档、周报、结项材料、个人主页 |
| 发布方 | 结构化发任务与 PRD、申请审阅、面试入项、节点看板、周报与结项评分 |
| 管理后台 | 认证辅助、等级、催办超时队列、邮件与系统配置 |
| 二期+ | 协调员、排行榜与积分、台账、可选开放方向提案；四期赞助 |

## 4. 环境与部署

| 环境 | 用途 |
| --- | --- |
| 开发 | Compose；假邮件或邮件捕获 |
| 预发 | 接近生产；小流量真邮件 |
| 生产 | whudev.org；HTTPS；DB 与文件备份 |

**备案。** 国内服务器需预留域名备案 / ICP 窗口。用户协议与隐私政策上线前占位。

## 5. 建设阶段（对齐需求分期）

1. **阶段 A · 一期 MVP。** 认证、结构化任务模板、申请书投递与 7 日催办、私信面试入项、周报评分、节点与结项材料、人工等级、Compose 部署。
2. **阶段 B · 二期。** 积分、排行榜、台账、协调员；可选开放方向提案。
3. **阶段 C · 三期。** GitHub App、建仓邀请、拆卡、PR 回写。
4. **阶段 D · 四期。** 赞助、多维排行、运营看板、体验。

## 6. 一期里程碑与分工

| 里程碑 | 产出 |
| --- | --- |
| M1 | 认证 + 角色；空壳布局 |
| M2 | 结构化任务/PRD + 申请书投递 + 私信/面试 |
| M3 | 入项 + 周报评分 + 节点状态机与结项材料 |
| M4 | 管理端等级与超时队列；部署；试运营招生 |

| 角色 | 职责 |
| --- | --- |
| 产品/运营 | 申请书与任务模板终稿、首批任务、补助文案 |
| 后端 | 认证、任务字段、申请书、状态机、邮件催办 |
| 前端 | 学生端 + 发布端（对齐 OSPP 详情信息密度） |
| 全栈支援 | 管理后台、私信 UI |
| 运维（可兼） | Docker/Nginx、证书、备案、备份 |

上线检查：

- [ ] Compose 可一键起；Nginx 配置可复现
- [ ] 生产 HTTPS 可访问 whudev.org
- [ ] 邮件验证与催办真实可达；站内信兜底
- [ ] 关键越权用例有服务端鉴权测试
- [ ] 备份与回滚说明（简版）

## 7. 风险与依赖

| 风险 | 缓解 |
| --- | --- |
| 邮箱域名校验 | 后缀白名单；验证链接；异常人工审核 |
| 邮件送达率 | 可靠 SMTP + SPF/DKIM；站内信兜底 |
| 备案 | 提前启动；内测临时访问 |
| 照搬 OSPP 过重 | 一期不做二审与电子签；只借字段与申请/结项形态 |
| GitHub（三期） | 一期结项用手动填 PR 链接 |
| 供给不足 | 预置 TA/开发任务；对接社群 |

公开参考：<https://summer.ospp.ac.cn/> 与 docs2026.summer.ospp.ac.cn。需求变更时先改分期，再改里程碑。
